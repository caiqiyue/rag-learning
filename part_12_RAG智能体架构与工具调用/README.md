# 第14节 RAG 智能体架构与工具调用

## 本节概述

本节将学习如何将智能体（Agent）架构引入 RAG 系统，使其具备自主决策和工具调用的能力。传统的 RAG 系统只能被动检索，而引入 Agent 后，智能体可以主动判断是否需要检索、选择哪个知识库、决定是否需要多步搜索。

**学习目标**
- 理解 RAG 智能体的核心组件（Agent、Tool、Memory）
- 掌握 ReAct 范式在 RAG 中的应用
- 能够构建具备工具调用能力的 RAG 智能体

**学习时长**：约 2-3 小时

**关联知识框架**
- kp_026: Agentic RAG 智能体 RAG - 结合 Agent 架构，让 RAG 系统具备自主决策能力
- kp_027: Modular RAG 模块化架构 - 模块化设计支持灵活组合与独立优化

## 14.1 为什么需要 RAG 智能体？

### 14.1.1 传统 RAG 的局限性

传统 RAG 系统的工作模式是「检索-生成」的线性流程，存在以下局限：

| 局限性 | 表现 | 影响 |
|--------|------|------|
| 被动检索 | 无论问题复杂与否都执行相同流程 | 资源浪费，效率低下 |
| 单次检索 | 只能进行一次检索，无法迭代 | 复杂问题回答不完整 |
| 单一知识库 | 无法选择适合问题的知识库 | 检索结果不精准 |
| 无法工具调用 | 不能访问外部 API 或执行计算 | 应用场景受限 |

### 14.1.2 Agentic RAG 的优势

Agentic RAG 将智能体的决策能力引入 RAG 系统：

```
                    ┌─────────────┐
                    │   Agent     │
                    │  (决策中心)  │
                    └──────┬──────┘
                           │
           ┌───────────────┼───────────────┐
           │               │               │
           ▼               ▼               ▼
    ┌────────────┐ ┌────────────┐ ┌────────────┐
    │  知识库1   │ │  知识库2   │ │  工具调用  │
    └────────────┘ └────────────┘ └────────────┘
```

**核心能力**：
- **自主决策**：判断是否需要检索，选择哪个知识库
- **迭代检索**：多步搜索，持续优化检索结果
- **工具调用**：访问外部 API、执行计算、调用其他服务
- **记忆管理**：维护对话历史和上下文

## 14.2 RAG 智能体核心组件

### 14.2.1 组件概述

RAG 智能体由三大核心组件构成：

| 组件 | 职责 | 说明 |
|------|------|------|
| **Agent** | 决策中心 | 理解用户意图，决定执行哪些动作 |
| **Tool** | 工具集合 | 检索工具、计算工具、API 调用等 |
| **Memory** | 记忆存储 | 对话历史、检索历史、中间结果 |

### 14.2.2 Agent 决策流程

```
       用户问题
            │
            ▼
    ┌───────────────┐
    │  意图理解      │  理解用户想要什么
    └───────┬───────┘
            │
            ▼
    ┌───────────────┐
    │  决策判断      │  是否需要检索？使用哪个工具？
    └───────┬───────┘
            │
       ┌────┴────┐
       │         │
       ▼         ▼
    执行      结束
    动作      回答
```

### 14.2.3 Tool 设计原则

工具是 Agent 执行动作的具体手段：

| 原则 | 说明 | 示例 |
|------|------|------|
| **明确性** | 工具功能清晰，职责单一 | `search_knowledge_base` 只负责检索 |
| **可观测性** | 工具执行结果可评估 | 返回检索结果和置信度 |
| **可组合性** | 工具可以串联使用 | 检索+计算+生成 |

## 14.3 ReAct 范式

### 14.3.1 什么是 ReAct

ReAct（Reasoning + Acting）是一种将推理和行动结合的范式，让 Agent 能够：

1. **Reasoning**：思考当前状态，分析问题
2. **Acting**：决定并执行动作
3. **Observing**：观察动作结果
4. **Reasoning**：基于结果继续推理

### 14.3.2 ReAct 在 RAG 中的应用

```
    ┌─────────────────────────────────────────────────────┐
    │                    ReAct 循环                       │
    ├─────────────────────────────────────────────────────┤
    │                                                     │
    │   Thought: 用户问的是XXX，我需要先检索               │
    │                    │                               │
    │                    ▼                               │
    │   Action: search_knowledge_base(query="XXX")      │
    │                    │                               │
    │                    ▼                               │
    │   Observation: 检索到3个相关文档                     │
    │                    │                               │
    │                    ▼                               │
    │   Thought: 检索结果足够，可以生成答案               │
    │                    │                               │
    │                    ▼                               │
    │   Action: generate_answer(context=docs)           │
    │                    │                               │
    │                    ▼                               │
    │   Final Response: 生成最终回答                      │
    │                                                     │
    └─────────────────────────────────────────────────────┘
```

### 14.3.3 ReAct 提示词模板

```python
REACT_TEMPLATE = """
你是一个智能助手，需要回答用户问题。

你可以在必要时使用以下工具：
- search_knowledge_base: 在知识库中搜索相关信息
- calculate: 执行数学计算
- generate_answer: 基于检索结果生成回答

开始！

Question: {question}
{scratchpad}
"""
```

## 14.4 RAG 智能体架构设计

### 14.4.1 模块化架构

RAG 智能体采用模块化设计，各模块职责清晰：

```
┌─────────────────────────────────────────────────────────┐
│                      RAG Agent                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐  │
│  │   Router   │───▶│  Executor   │───▶│   Output    │  │
│  │  (路由模块) │    │  (执行模块) │    │  (输出模块) │  │
│  └─────────────┘    └─────────────┘    └─────────────┘  │
│         │                  │                  │         │
│         ▼                  ▼                  ▼         │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐  │
│  │   Memory   │    │    Tool     │    │  Response  │  │
│  │ (记忆模块)  │    │  (工具模块) │    │  Generator │  │
│  └─────────────┘    └─────────────┘    └─────────────┘  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 14.4.2 路由模块（Router）

负责理解用户意图，决定是否需要检索以及使用哪个知识库：

| 功能 | 说明 |
|------|------|
| 意图分类 | 判断问题是需要检索还是直接回答 |
| 知识库选择 | 选择合适的知识库或工具 |
| 查询改写 | 将用户问题改写为检索 query |

### 14.4.3 执行模块（Executor）

负责执行具体的检索和工具调用：

| 功能 | 说明 |
|------|------|
| 工具调用 | 调用检索工具或其他工具 |
| 结果评估 | 评估检索结果的质量 |
| 迭代决策 | 决定是否需要继续检索 |

### 14.4.4 记忆模块（Memory）

管理对话历史和中间结果：

| 类型 | 说明 | 用途 |
|------|------|------|
| 对话历史 | 保存用户和助手的对话 | 维护上下文 |
| 检索历史 | 保存历史检索结果 | 避免重复检索 |
| 中间结果 | 保存推理过程中的状态 | 支持多步推理 |

## 14.5 工具调用实现

### 14.5.1 工具定义

RAG 智能体中的工具需要遵循统一的接口规范：

```python
class BaseTool:
    """工具基类，所有工具都需要继承此类"""
    name: str  # 工具名称
    description: str  # 工具描述

    def execute(self, **kwargs) -> Any:
        """执行工具，返回结果"""
        raise NotImplementedError
```

### 14.5.2 常用工具类型

| 工具类型 | 功能 | 示例 |
|----------|------|------|
| 检索工具 | 在知识库中检索 | `VectorSearchTool`、`BM25SearchTool` |
| 计算工具 | 执行数学计算 | `Calculator`、`UnitConverter` |
| API 工具 | 访问外部服务 | `WeatherAPI`、`SearchAPI` |
| 生成工具 | 生成最终答案 | `AnswerGenerator` |

## 14.8 关键要点总结

1. **Agentic RAG 优势**：自主决策、迭代检索、工具调用、记忆管理

2. **三大核心组件**：
   - Agent：决策中心，理解意图并决定动作
   - Tool：执行具体操作的工具集合
   - Memory：管理对话历史和中间结果

3. **ReAct 范式**：Reasoning（推理） + Acting（行动） + Observing（观察）的循环

4. **模块化设计**：Router（路由）、Executor（执行）、Memory（记忆）分工明确
