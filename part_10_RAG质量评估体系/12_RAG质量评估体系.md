## 12.1 为什么需要评估 RAG？

### 12.1.1 没有评估的代价

没有系统评估的 RAG 系统如同"盲人骑瞎马"，会面临以下常见问题：

| 问题类型 | 表现 | 影响 |
|---------|------|------|
| 检索质量差 | 检索不到相关内容 | 回答不相关或错误 |
| 生成幻觉 | 回答与文档内容矛盾 | 误导用户，损害信任 |
| 上下文丢失 | 回答不完整 | 无法解决复杂问题 |
| 性能问题 | 响应缓慢 | 用户体验差 |

### 12.1.2 评估的三个维度

RAG 评估可以从三个维度进行分析：

```
           检索质量
              /    \
             /      \
            /        \
           /    生成   \
          /    质量    \
         ───────────────
           整体效果
```

| 维度 | 关注点 | 核心指标 |
|------|--------|----------|
| **检索质量** | 检索到的文档是否相关 | 召回率、准确率、MRR、NDCG |
| **生成质量** | 回答是否准确、完整 | Faithfulness、Answer Relevance |
| **整体效果** | 系统是否满足用户需求 | RAGAS Score、用户体验 |

## 12.2 检索质量评估

### 12.2.1 核心指标

**1. 精确率（Precision）**

检索结果中相关文档的比例。

```
Precision = 相关文档数 / 检索总数
```

**2. 召回率（Recall）**

相关文档被检索到的比例。

```
Recall = 检索到的相关文档数 / 实际相关文档总数
```

**3. F1 分数**

精确率和召回率的调和平均，综合评估检索效果。

```
F1 = 2 × Precision × Recall / (Precision + Recall)
```

**4. MRR（Mean Reciprocal Rank）**

第一个相关结果的位置好坏。MRR = 1 表示第一个结果就是相关的。

```
MRR = mean(1 / rank_i)  其中 rank_i 是第 i 个相关文档的位置
```

**5. NDCG（Normalized Discounted Cumulative Gain）**

考虑排序位置的评估指标，越靠前的相关结果权重越高。

```
NDCG = DCG / IDCG
```

### 12.2.2 指标解读表

| 指标 | 含义 | 理想值 | 说明 |
|------|------|--------|------|
| **Precision** | 准确率 | 高 | 检索结果中相关的比例 |
| **Recall** | 召回率 | 高 | 相关文档被检索到的比例 |
| **F1** | 综合评估 | 高 | 精确率和召回率的平衡 |
| **MRR** | 排名质量 | 高（接近1） | 第一个相关结果的位置 |
| **NDCG** | 排序效果 | 高（接近1） | 考虑位置的排序评估 |

## 12.3 生成质量评估

### 12.3.1 RAGAS 核心指标

RAGAS（Retrieval-Augmented Generation Assessment）是专门评估 RAG 系统的开源框架。

**1. Faithfulness（忠实度）**

回答是否忠实于检索到的内容，没有编造信息。

- 得分范围：0 到 1
- 理想值：1.0（完全忠实）
- 评估方法：检查回答中的事实是否都能在上下文中找到依据

**2. Answer Relevance（回答相关性）**

回答与问题的相关程度，是否完整解决了用户疑问。

- 得分范围：0 到 1
- 理想值：1.0（高度相关）
- 评估方法：分析回答长度、内容覆盖率和问题针对性

**3. Context Precision（上下文精确度）**

检索上下文中有多少是真正相关的内容。

- 得分范围：0 到 1
- 理想值：1.0（完全精确）
- 评估方法：检查上下文的重复度和内容质量

**4. Context Recall（上下文召回率）**

检索上下文是否覆盖了标准答案的信息。

- 得分范围：0 到 1
- 理想值：1.0（完全召回）
- 评估方法：对比标准答案和检索上下文的覆盖情况

### 12.3.2 指标解读表

| 指标 | 说明 | 理想值 | 重要性 |
|------|------|--------|--------|
| **Faithfulness** | 回答对检索内容的忠实程度 | 1.0 | 高（防止幻觉） |
| **Answer Relevancy** | 回答与问题的相关程度 | 1.0 | 高（解决用户问题） |
| **Context Precision** | 检索上下文的精确程度 | 1.0 | 中 |
| **Context Recall** | 检索上下文包含正确答案的程度 | 1.0 | 中 |

## 12.4 Bad Case 分析

### 12.4.1 错误分类体系

Bad Case（坏案例）是指 RAG 系统回答错误或不理想的案例。

**检索问题**

| 错误类型 | 描述 | 严重程度 |
|---------|------|----------|
| `retrieval_empty` | 召回为空（没有检索到任何内容） | 高 |
| `retrieval_irrelevant` | 召回不相关（检索到的内容与问题无关） | 高 |
| `retrieval_wrong` | 召回了错误内容（检索到了误导性信息） | 高 |
| `retrieval_incomplete` | 召回不完整（遗漏了重要的相关信息） | 中 |

**生成问题**

| 错误类型 | 描述 | 严重程度 |
|---------|------|----------|
| `hallucination` | 幻觉（回答中包含上下文中没有的信息） | 严重 |
| `incomplete` | 回答不完整（没有完整回答问题） | 中 |
| `contradict` | 回答矛盾（回答内容与上下文矛盾） | 高 |
| `format_error` | 格式错误（输出格式不符合要求） | 低 |
| `off_topic` | 答非所问（没有针对问题回答） | 高 |

### 12.4.2 分析流程

```
       测试用例
            │
            ▼
    ┌───────────────┐
    │  错误类型检测  │
    └───────┬───────┘
            │
            ▼
    ┌───────────────┐
    │   分类统计     │
    └───────┬───────┘
            │
            ▼
    ┌───────────────┐
    │  生成优化建议  │
    └───────────────┘
```

## 12.5 优化策略对照表

| 问题 | 可能原因 | 优化策略 |
|------|----------|----------|
| 召回为空 | Embedding 质量差 | 换用更好的 Embedding 模型 |
| 召回不相关 | 切分策略不当 | 调整 chunk_size 和 overlap |
| 召回了错误内容 | 知识库包含错误信息 | 清理知识库，增加验证 |
| 幻觉严重 | 检索内容不准确 | 优化检索，增加引用验证 |
| 回答不完整 | 上下文不足 | 调整召回数量，增加 top_k |
| 回答矛盾 | 多文档冲突 | 增加冲突检测逻辑 |
| 响应慢 | 向量库查询慢 | 添加索引优化，使用更快的向量库 |

## 12.8 关键要点总结

1. **评估三维度**：检索质量（Precision/Recall/F1/MRR/NDCG）、生成质量（Faithfulness/Answer Relevance）、整体效果

2. **RAGAS 四大指标**：
   - Faithfulness：防止幻觉，确保回答基于检索内容
   - Answer Relevance：确保回答针对问题
   - Context Precision：检索内容的精确程度
   - Context Recall：检索内容对答案的覆盖程度

3. **Bad Case 分析**：通过分类统计定位问题根因，指导优化方向

4. **持续迭代**：建立 PDCA 循环（Plan-Do-Check-Act），持续优化 RAG 系统
