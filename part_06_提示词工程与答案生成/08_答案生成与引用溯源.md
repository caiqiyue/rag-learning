# 第08节 答案生成与引用溯源

## 学习目标

1. **理解LLM答案生成的工作原理**：掌握RAG系统中如何利用检索到的文档生成最终答案
2. **掌握生成答案时引用source chunks的方法**：学会在答案中标注引用来源，实现答案可溯源
3. **能够构建可溯源的RAG答案生成流程**：了解完整的答案生成管道和最佳实践

## 知识点讲解

### 1. 答案生成的核心原理

在RAG系统中，答案生成是整个流程的最后一环，负责将检索到的相关文档与用户问题结合，生成最终的自然语言回答。

**答案生成的基本流程**：

1. **检索阶段**：从向量数据库中检索与查询相关的Top-K文档 chunks
2. **上下文组装**：将检索到的文档内容组装成提示词上下文
3. **提示词构建**：使用提示词模板将用户问题、检索上下文、输出格式要求组合
4. **LLM生成**：调用大语言模型生成最终答案
5. **引用溯源**：在答案中标记引用来源，确保可追溯性

### 2. 提示词模板设计

提示词模板是答案生成质量的关键因素。一个好的提示词模板应该包含以下要素：

| 要素 | 作用 | 示例 |
|------|------|------|
| 系统角色 | 设定AI的专业能力范围 | "你是一位专业的技术文档助手" |
| 任务描述 | 明确回答的具体任务 | "根据提供的上下文信息回答问题" |
| 上下文 | 插入检索到的文档内容 | Context: {context} |
| 用户问题 | 明确的问题 | Question: {question} |
| 输出格式 | 答案的结构要求 | "请用简洁的语言回答，并标注引用来源" |
| 约束条件 | 回答的边界限制 | "如果上下文信息不足，请明确说明" |

### 3. 引用溯源的重要性

引用溯源让答案的每个声明都可以追溯到具体的source chunk，有以下作用：

- **可靠性验证**：用户可以核实答案的准确性
- **减少幻觉**：LLM被限制在提供的上下文中生成，降低虚构信息的风险
- **知识管理**：追踪答案来源，便于知识更新和维护
- **信任建立**：透明的引用机制增强用户对系统的信任

### 4. 引用格式设计

常见的引用格式有以下几种：

**方式一：内联引用**
```
答案内容 [来源1: 文档A, 来源2: 文档B]
```

**方式二：脚注式**
```
答案内容

参考来源：
[1] 文档A - chunk_id_1
[2] 文档B - chunk_id_2
```

**方式三：编号标注**
```
根据文档[1]和文档[2]，答案内容如下...
```

### 5. QueryEngine响应合成模式

LlamaIndex的QueryEngine支持多种响应合成模式：

| 模式 | 原理 | 适用场景 |
|------|------|----------|
| `compact` | 将多个检索结果压缩合并后一次性生成 | 检索结果数量较多时 |
| `refine` | 逐步迭代优化答案 | 需要精细答案的场景 |
| `compact_refine` | 先压缩再迭代优化 | 平衡效率和质量的场景 |
| `tree_summarize` | 分层总结后生成 | 需要全面理解文档的场景 |
