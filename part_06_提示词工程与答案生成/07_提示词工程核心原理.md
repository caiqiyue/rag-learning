## 一、提示词工程概述

### 1.1 什么是提示词工程？

**提示词工程**（Prompt Engineering）是设计和优化输入给大语言模型的文本指令的艺术和科学。在RAG系统中，提示词决定了如何将检索到的文档与用户问题组合，使LLM能够生成准确、有针对性的回答。

### 1.2 提示词工程在RAG中的作用

```
用户问题 → 检索器 → 相关文档 → 提示增强 → LLM → 最终答案
                                    ↑
                              提示词模板
```

提示词模板的核心价值：
- **指令聚焦**：明确告诉LLM需要基于检索内容回答，而非依靠自己的知识
- **格式规范**：设定回答的结构、长度、风格等要求
- **边界控制**：限制LLM不要回答超出知识库范围的问题
- **引用追溯**：要求LLM在回答中标注文档来源

### 1.3 提示词的三种类型

| 类型 | 作用 | 示例 |
|------|------|------|
| **系统提示词** | 定义AI角色、行为规范、回答风格 | "你是一位专业的技术支持工程师" |
| **用户提示词** | 包含用户实际问题和原始问题 | "如何重置XX型号路由器的密码？" |
| **上下文提示词** | 包含检索到的相关文档内容 | "参考文档：[文档1]...[文档2]..." |

## 二、三种提示词的设计方法

### 2.1 系统提示词设计

系统提示词设定AI的基础角色和行为边界，是整个提示的基调。

**设计原则**：
1. **明确角色定位**：让LLM知道自己是什么身份
2. **设定回答范围**：明确可以回答和不可以回答的问题
3. **规范输出格式**：设定回答的结构要求
4. **强调知识运用**：要求必须基于提供的上下文回答

**企业级系统提示词模板**：

```
你是一名专业的{领域}技术顾问。你的职责是：
1. 基于提供的参考文档，准确回答用户的问题
2. 如果文档中没有相关信息，明确告知用户"我无法从文档中找到答案"
3. 回答时尽量引用文档中的具体内容，并标注来源
4. 回答要简洁、专业、清晰，避免冗余

回答格式要求：
- 直接回答问题，无需重复问题背景
- 使用Markdown格式组织内容
- 如有必要，用项目符号列出步骤或要点
- 在回答末尾标注参考来源
```

### 2.2 用户提示词设计

用户提示词是用户实际输入的问题，需要与上下文结合形成完整的增强提示。

**设计原则**：
1. **提取核心问题**：从用户输入中提取真正的问题
2. **保留原始表述**：保留用户问题的原始问法
3. **补充上下文信息**：添加对话历史（如有）

**用户提示词模板**：

```
用户问题：{user_question}

请根据上述参考文档，回答用户的问题。
```

### 2.3 上下文提示词设计

上下文提示词包含检索到的相关文档，是LLM回答问题的"资料库"。

**设计原则**：
1. **包含足够信息**：提供回答所需的全部相关内容
2. **标注文档来源**：每段文档标注来源（文件名、页码等）
3. **限制信息量**：避免上下文过长导致迷失或超限
4. **优先级排序**：最重要的文档放在最前面

**上下文提示词模板**：

```
## 参考文档

### 文档1：{doc_title}（来源：{doc_source}）
{relevant_content_1}

### 文档2：{doc_title}（来源：{doc_source}）
{relevant_content_2}

...（如有更多文档）

---
请基于以上参考文档回答问题。
```

## 三、增强提示词模板的构建

### 3.1 标准RAG增强提示词模板

在RAG系统中，增强提示词将检索到的文档与用户问题组合，形成完整的输入。

**基础模板结构**：

```
系统提示词部分：
---
你是专业的技术顾问。请基于提供的参考文档回答问题。
如果你无法从文档中找到答案，请明确告知。
---

上下文部分：
---
## 参考文档

[文档1] 标题：XXX
内容：...
来源：XXX.pdf

[文档2] 标题：YYY
内容：...
来源：YYY.docx
---

用户问题部分：
---
用户问题：如何设置路由器的访客网络？
---
```

### 3.2 企业级RAG增强提示词模板

生产环境需要更精细的提示词设计：

**模板要素**：
1. **任务说明**：明确当前任务类型
2. **角色设定**：AI的身份和专业知识范围
3. **指令约束**：回答时的具体规则
4. **输出格式**：回答的格式要求
5. **安全边界**：不能回答的问题类型

**企业级模板示例**：

```
【任务类型】：技术问题解答
【角色】：专业技术支持工程师
【专业领域】：{domain}

【指令要求】：
1. 必须基于参考文档内容回答，不依赖自身知识
2. 如果文档中没有相关信息，回答"抱歉，参考文档中没有找到相关信息"
3. 回答时引用具体文档内容，标注来源
4. 回答简洁明了，直击问题核心
5. 避免主观臆测，只陈述文档中明确包含的信息

【输出格式】：
- 直接回答问题
- 重要信息用加粗标注
- 引用内容用引用格式
- 末尾注明参考文档列表

【安全边界】：
- 不回答涉及隐私、安全、伦理的问题
- 不猜测或编造文档中没有的信息
- 不提供文档范围之外的操作建议

【参考文档】：
{documents}

【用户问题】：
{question}

【回答】：
```

## 四、提示词参数调优

### 4.1 关键参数

| 参数 | 说明 | 建议值 |
|------|------|--------|
| **temperature** | 控制随机性，值越低越确定性 | 0.1~0.3（事实性问题） |
| **max_tokens** | 最大输出token数 | 根据回答长度需求设置 |
| **top_p** | 核采样参数 | 0.9~0.95 |
| **presence_penalty** | 话题新鲜度惩罚 | 0~0.5 |

### 4.2 参数调整建议

**事实性问答**（如技术支持）：
- temperature：0.1~0.2（低随机性）
- max_tokens：500~1000
- 确保回答准确性优先

**创意性任务**（如方案设计）：
- temperature：0.5~0.7
- max_tokens：1500~2000
- 允许一定创造性

## 五、LlamaIndex中的提示词模板

### 5.1 QueryEngine的提示词机制

QueryEngine是LlamaIndex提供的端到端问答引擎，它整合了检索器、提示模板和LLM：

```
QueryEngine内部流程：
1. 检索器根据用户问题检索相关文档
2. 将检索结果传入提示模板
3. 组装成增强提示词
4. 发送给LLM生成答案
5. 返回最终回答
```

### 5.2 自定义提示模板

在LlamaIndex中可以自定义提示模板：

```python
from llama_index.core import PromptTemplate

# 定义自定义提示模板
prompt_template = PromptTemplate(
    "【角色】你是专业的{domain}技术支持工程师\n"
    "【任务】基于参考文档回答用户问题\n"
    "【要求】必须引用文档内容，标注来源\n"
    "\n"
    "【参考文档】\n"
    "{context_str}\n"
    "\n"
    "【用户问题】：{query_str}\n"
    "\n"
    "【回答】："
)
```
