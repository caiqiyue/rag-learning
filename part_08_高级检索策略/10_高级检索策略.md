1. 理解上下文压缩和查询变换的原理

- **kp_022**: Self-RAG自我检索增强 - Self-RAG让模型在生成过程中自适应判断是否需要检索。

## 一、背景与问题引入

### 1.1 基础RAG的局限性

基础RAG（Naive RAG）虽然简单直接，但在实际应用中面临诸多挑战：

| 问题类型 | 具体表现 | 影响 |
|----------|----------|------|
| **语义理解偏差** | 用户问题表达与文档表述存在差异 | 检索不到相关内容 |
| **上下文稀释** | 关键信息淹没在大量无关内容中 | 答案质量下降 |
| **多跳推理困难** | 答案需要跨越多个文档片段 | 无法正确关联 |
| **检索时机不当** | 所有问题都触发检索，效率低下 | 计算资源浪费 |

### 1.2 高级检索策略的价值

高级检索策略通过更智能的检索和后处理机制，解决上述问题：

```
基础RAG → 高级检索策略
    ↓
语义匹配 + 上下文压缩 + 自适应检索
```

## 二、上下文压缩 Contextual Compression

### 2.1 什么是上下文压缩？

**上下文压缩**是在检索后对文档进行处理，提取最相关的部分，同时去除冗余信息。这解决了"关键信息淹没在大量内容中"的问题。

### 2.2 工作原理

```
原始文档 → LLM压缩 → 精炼文档块
(可能1000字)    ↓       (可能200字)
            提取关键信息
            去除冗余
```

### 2.3 压缩策略类型

| 策略 | 原理 | 适用场景 |
|------|------|----------|
| **LLMCompactor** | 使用LLM判断并提取关键句 | 需要高精度压缩 |
| **RecursiveCompression** | 递归分割并选择最相关部分 | 长文档处理 |
| **ContextualCompression** | 保留上下文信息的压缩 | 维持语义完整 |

### 2.4 优势与局限

**优势**：
- 减少无关信息干扰
- 提高生成质量
- 降低Token消耗

**局限**：
- 额外的LLM调用开销
- 压缩过程可能丢失细节

## 三、查询变换 Query Transformation

### 3.1 什么是查询变换？

**查询变换**是将用户复杂的原始问题转换为更适合检索的形式，包括：
- Query Rewriting（重写）：改写问题表述
- Query Decomposition（分解）：拆分为多个子问题
- Query Expansion（扩展）：补充相关概念

### 3.2 Query Rewriting

将用户口语化、模糊的表达转化为清晰的检索查询。

**示例**：
```
原始问题："那个关于机器学习的课程"
重写后："机器学习课程介绍"

原始问题："怎么才能不让电脑中毒？"
重写后："电脑病毒防护措施"
```

### 3.3 Query Decomposition

将复杂问题拆分为多个简单子问题，分别检索后再合并答案。

**示例**：
```
原始问题："谁提出了Transformer架构，它的主要作者是谁？"
分解后：
- 子问题1：Transformer架构是谁提出的？
- 子问题2：Transformer论文的主要作者有哪些？

合并答案后返回完整结果
```

### 3.4 HyDE（Hypothetical Document Embeddings）

HyDE是一种创新的检索策略，其核心思想是"让LLM先猜测答案，再用这个猜测去找相关文档"。

**工作流程**：
```
用户问题 → LLM生成"假设答案" → 用假设答案检索 → 找到真实相关文档
```

**为什么HyDE有效？**
- 假设答案可能与真实文档的表述更接近
- 生长的答案包含更多可能相关的概念
- 检索空间从"问题"扩展到"答案"

## 四、Sentence Window Retrieval

### 4.1 核心思想

Sentence Window Retrieval将文档分割为单个或几个句子的窗口，检索时不仅返回匹配的句子，还返回其周围上下文。

### 4.2 工作原理

```
原文档："机器学习是人工智能的子领域。它使用数据来训练模型。深度学习是机器学习的分支。"

用户查询："什么是机器学习？"

检索过程：
1. 定位最相关句子："机器学习是人工智能的子领域。"
2. 扩展上下文窗口（前后各取2句话）
3. 返回扩展后的完整上下文
```

### 4.3 优势

| 优势 | 说明 |
|------|------|
| **精确匹配** | 精确句子级别匹配保证相关性 |
| **上下文完整** | 保留周围句子维持语义完整 |
| **灵活性高** | 窗口大小可调 |

---

## 五、Parent Document Retrieval

### 5.1 核心思想

Parent Document Retrieval维护父子文档层级关系：先检索小文档块，如果相关，再获取其父文档进行增强。

### 5.2 工作原理

```
父文档（整页内容）
    ↓ 分割
子文档块1 | 子文档块2 | 子文档块3 | ...

检索过程：
1. 用问题检索子文档块
2. 找到相关子文档后，获取其父文档
3. 用父文档内容增强答案
```

### 5.3 与Sentence Window的区别

| 策略 | 粒度 | 增强方式 | 适用场景 |
|------|------|----------|----------|
| Sentence Window | 句子级 | 扩大窗口 | 精确信息查找 |
| Parent Document | 块级 | 返回父文档 | 需要完整上下文 |

## 六、Self-RAG 自我检索增强

### 6.1 什么是Self-RAG？

Self-RAG是斯坦福大学提出的自适应检索框架，核心思想是让LLM自己判断"需不需要检索"。

### 6.2 工作原理

Self-RAG引入特殊的反思token，让模型在生成过程中判断：

| 反思Token | 含义 | 动作 |
|-----------|------|------|
| **[Retrieval]** | 需要检索 | 执行检索 |
| **[No Retrieval]** | 不需要检索 | 直接生成 |
| **[Relevant]** | 检索结果相关 | 使用检索结果 |
| **[Irrelevant]** | 检索结果不相关 | 忽略/降级 |

### 6.3 生成过程

```
用户问题 → LLM判断是否检索
    ↓
是 → 检索 → 判断相关性 → 相关则使用 → 生成
    ↓
否 → 直接基于自身知识生成
```

### 6.4 优势

- **自适应**：避免不必要的检索，提升效率
- **自验证**：通过反思token验证检索结果质量
- **可控制**：可以通过反思token追踪推理过程

## 七、GraphRAG 图谱增强检索

### 7.1 什么是GraphRAG？

GraphRAG是微软提出的基于知识图谱的检索增强方法，利用图结构的关系来增强检索和生成能力。

### 7.2 核心概念

| 概念 | 说明 |
|------|------|
| **实体节点** | 知识图谱中的实体（如人物、地点、概念） |
| **关系边** | 实体之间的关系 |
| **社区** | 相关的实体和关系形成的簇 |

### 7.3 工作流程

```
文档 → 知识图谱构建 → 图索引 → 社区检索 → 答案生成
    ↓
提取实体和关系

用户查询 → 定位相关社区 → 社区摘要 → 增强上下文
```

### 7.4 优势

| 优势 | 说明 |
|------|------|
| **关系推理** | 能回答需要关联多个实体的问题 |
| **全局理解** | 社区级别摘要提供文档概览 |
| **减少幻觉** | 基于图结构的事实关联 |

---

## 八、CRAG 纠正式检索增强

### 8.1 什么是CRAG？

CRAG（Corrective Retrieval Augmented Generation）是一种主动纠正低质量检索结果的策略。

### 8.2 决策机制

```
检索结果 → 质量评估
    ↓
质量高 → 直接用于生成
质量中 → 知识去污（Knowledge Refinement）
质量低 → 网络搜索替代
```

### 8.3 知识去污

当检索结果质量中等时，对结果进行过滤和提纯：
- 过滤掉不相关的片段
- 保留核心相关内容
- 重新组织后用于生成

## 九、实际应用建议

### 9.1 策略选择指南

| 场景 | 推荐策略 |
|------|----------|
| 短查询、多样化表达 | HyDE + Query Rewriting |
| 需要完整上下文 | Parent Document Retrieval |
| 精确信息查找 | Sentence Window |
| 自适应效率要求高 | Self-RAG |
| 复杂关系推理 | GraphRAG |
| 检索质量不稳定 | CRAG |

### 9.2 组合使用示例

实际应用中常组合多种策略：

```
用户问题
    ↓
Query Rewriting（改写问题）
    ↓
混合检索（向量 + BM25）
    ↓
Sentence Window（扩展上下文）
    ↓
Rerank（精排）
    ↓
Contextual Compression（压缩）
    ↓
答案生成
```

### 9.3 注意事项

1. **评估优先**：先评估基础RAG效果，再针对性引入高级策略
2. **开销平衡**：高级策略带来更好效果，但也增加复杂度和开销
3. **可观测性**：引入日志和监控，跟踪各环节效果
4. **迭代优化**：根据实际效果调整策略组合

## 十一、总结

| 策略 | 核心思想 | 解决的问题 |
|------|----------|------------|
| **上下文压缩** | 去除冗余，提取精华 | 信息稀释 |
| **查询变换** | 改写、分解、扩展问题 | 语义偏差 |
| **Sentence Window** | 句子级检索+上下文扩展 | 精确但需上下文 |
| **Parent Document** | 父子文档层级增强 | 完整上下文需求 |
| **Self-RAG** | 模型自主判断检索时机 | 效率与质量平衡 |
| **GraphRAG** | 知识图谱关系推理 | 多跳复杂问题 |
| **CRAG** | 主动纠正低质量检索 | 检索结果不可靠 |

高级检索策略是构建企业级RAG系统的必备能力，合理组合使用可显著提升检索和生成质量。
