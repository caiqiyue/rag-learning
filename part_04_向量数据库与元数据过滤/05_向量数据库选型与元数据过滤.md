## 一、向量数据库选型概述

### 1.1 什么是向量数据库

向量数据库是专门用于存储和检索向量化数据（Embeddings）的系统。在RAG应用中，文档首先被切分成片段，然后通过Embedding模型转换为向量表示，存储在向量数据库中。检索时，用户查询同样被转换为向量，通过相似度计算找到最相关的文档片段。

**向量数据库的核心价值：**
- 海量向量数据的高效存储和检索
- 支持多种相似度度量（余弦相似度、欧氏距离等）
- 解决"大海捞针"问题，快速定位相关内容

### 1.2 主流向量数据库对比

| 数据库 | 适用规模 | 部署方式 | 成本 | 适用场景 |
|--------|----------|----------|------|----------|
| **Chroma** | <100万向量 | 本地 | 免费开源 | POC验证、快速原型、小型项目 |
| **FAISS** | 任意规模 | 本地 | 免费开源 | 大规模数据、高精度需求、有技术团队 |
| **Milvus** | 百万-亿级 | 云原生/Docker | 中等（自建） | 中等规模生产、需要水平扩展 |
| **Pinecone** | 任意规模 | 完全托管 | 按量付费 | Serverless架构、快速扩展、无运维能力 |
| **Qdrant** | 百万-亿级 | 云原生/本地 | 中等 | 需要高性能HNSW索引 |
| **Weaviate** | 任意规模 | 云原生/本地 | 中等 | 混合查询、多模态数据 |

## 三、FAISS - 高效本地大规模检索

### 特点
- Facebook开源的向量检索库，专注高效相似度搜索
- 支持数十亿级向量索引，适合大规模数据
- 提供多种索引类型（IVF、HNSW、PQ等），平衡精度与性能
- 纯本地部署，无额外成本

### 索引类型选择
- **IndexFlatL2**：精确检索，适合小数据量
- **IndexIVFFlat**：聚类索引，平衡精度与速度
- **IndexHNSW**：图索引，高查询速度但内存占用大

### 适用场景
- 大规模本地数据部署
- 高精度需求场景
- 成本敏感型企业

## 六、选型决策指南

### 快速决策树

```
数据规模 < 100万向量？
    │
    ├─ 是 → 需要快速验证？
    │       │
    │       ├─ 是 → Chroma（免费、快速）
    │       └─ 否 → FAISS（高精度）
    │
    └─ 否 → 有运维团队？
            │
            ├─ 是 → Milvus（自建）
            └─ 否 → Pinecone（托管）
```

### 关键考虑因素

| 因素 | 说明 |
|------|------|
| **向量维度** | 大多数模型输出1536维，部分模型需要更大维度 |
| **距离度量** | cosine余弦（常用）、euclidean欧氏、dotproduct点积 |
| **索引类型** | Flat（精确）、IVF（聚类）、HNSW（图索引）、PQ（量化压缩） |
| **扩展性** | 数据增长预估，决定选择单机还是分布式方案 |
| **成本** | 云服务按存储和查询量收费，本地方案有运维成本 |
| **混合过滤** | 是否需要支持元数据标量过滤（大部分场景需要） |

## 七、元数据结构设计

### 7.1 常见元数据字段

| 字段名 | 类型 | 说明 | 示例值 |
|--------|------|------|--------|
| source | string | 文档来源/文件名 | "合同文档.pdf" |
| page_number | int | 页码 | 5 |
| element_type | string | 元素类型 | "Text"/"Table"/"Image" |
| category | string | 文档分类 | "技术文档"/"商务文档" |
| year | int | 年份 | 2024 |
| author | string | 作者 | "张三" |
| department | string | 部门 | "研发部" |
| confidential | bool | 是否机密 | true/false |
| tags | list | 标签列表 | ["AI", "RAG", "向量"] |
| language | string | 语言 | "中文"/"英文" |

### 7.2 元数据设计原则

1. **区分度优先**：选择区分度高的字段（如类别、类型）
2. **避免高基数字段**：避免在完整文本内容等高基数字段上过滤
3. **时间范围是常见场景**：年份、日期字段是最高频的过滤条件

## 八、元数据过滤查询

### 8.1 MetadataFilter核心概念

MetadataFilter用于在向量相似度检索的基础上添加元数据过滤条件，可以显著缩小检索范围，提高查询精度。

**LlamaIndex中的过滤器类：**

- **MetadataFilter**：单个过滤条件
  - `key`：元数据字段名
  - `value`：过滤值
  - `operator`：过滤操作符（默认EQ）

- **MetadataFilters**：多个过滤条件组合
  - `filters`：多个MetadataFilter列表
  - `condition`：条件逻辑（AND/OR）

### 8.2 常用过滤操作符

| 操作符 | 说明 | 示例 |
|--------|------|------|
| `FilterOperator.EQ` | 等于 | `year == 2024` |
| `FilterOperator.NE` | 不等于 | `confidential != True` |
| `FilterOperator.GT` | 大于 | `year > 2023` |
| `FilterOperator.GTE` | 大于等于 | `year >= 2020` |
| `FilterOperator.LT` | 小于 | `year < 2025` |
| `FilterOperator.LTE` | 小于等于 | `year <= 2025` |
| `FilterOperator.CONTAINS` | 包含（字符串） | `source contains "合同"` |
| `FilterOperator.IN` | 属于列表 | `department in ["研发部", "产品部"]` |

### 8.3 复合过滤示例

```python
from llama_index.core.vector_stores import MetadataFilter, MetadataFilters, FilterOperator, FilterCondition

# 复合过滤：研发部的非机密文本文档
filters = MetadataFilters(
    filters=[
        MetadataFilter(key="department", value="研发部", operator=FilterOperator.EQ),
        MetadataFilter(key="confidential", value=False, operator=FilterOperator.EQ),
        MetadataFilter(key="element_type", value="Text", operator=FilterOperator.EQ),
    ],
    condition=FilterCondition.AND  # 三个条件同时满足
)

retriever = index.as_retriever(filters=filters, similarity_top_k=5)
results = retriever.retrieve("RAG系统部署指南")
```

### 8.4 常见业务场景

| 场景 | 过滤条件 | 查询内容 |
|------|----------|----------|
| 用户反馈分析 | `year=2024, category="用户反馈"` | 产品体验问题总结 |
| 合同条款检索 | `source contains "合同", year>=2023` | 违约金条款 |
| 研发部知识库 | `department="研发部", confidential=False` | 代码规范要求 |
| 多语言文档 | `language="英文", tags contains "RAG"` | RAG deployment guide |

### 8.5 各数据库过滤能力对比

| 数据库 | 过滤能力 | 性能 | 适用场景 |
|--------|----------|------|----------|
| Chroma | 基础 | 内存级快速 | 小规模数据、简单条件 |
| Milvus | 强大 | 列式优化 | 大规模数据、复杂条件 |
| Pinecone | 强大 | 云端优化 | 任意规模、云原生 |
| FAISS | 弱（需过滤） | 依赖索引 | 不推荐元数据过滤 |
