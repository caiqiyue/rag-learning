# 内容构建技能 (Content Builder Skill)

## 概述

一个基于多智能体协作的学习内容构建系统。通过阶段式智能体工作流，将任意技术主题拆解为企业级知识框架，并生成配套的教学文档、代码示例和实验内容。

**适用场景：** 大模型微调，强化学习，或任何需要系统性学习内容的技术主题

**核心价值：**
- 企业级知识框架设计
- 初学者友好的教学内容的生成
- 代码案例 + 文档的双轨输出
- 自动化质量审核与修复

## 阶段详细说明

### 阶段 1: 需求解析

**输入参数（从用户获取）：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `topic` | 学习主题 | "RAG检索增强生成" |
| `audience` | 目标受众 | "初学者" |
| `level` | 深度级别 | "企业级快速入门" |
| `duration` | 学习时长（可选） | "2周" |
| `tech_stack` | 技术栈偏好（可选） | "Python, LangChain" |
| `course_name` | 课程名称（自动生成或指定） | "RAG实战课程" |

**输出：**
```json
{
  "topic": "RAG检索增强生成",
  "course_name": "RAG实战课程",
  "audience": "初学者",
  "level": "企业级快速入门",
  "duration": "2-3周",
  "tech_stack": ["Python", "LangChain", "向量数据库"],
  "created_at": "2026-05-29"
}
```

**持久化：** 创建 `{course_name}/README.md` 的 `## 需求解析` 章节

---

### 阶段 2: 资料迁移

**执行者：** 主智能体

**职责：**
1. 扫描用户提供原始资料的目录/路径
2. 将**所有**原始资料原样移动到 `raw-material/` 目录
3. 保持原始目录结构和文件名
4. **不分析、不挑选** - 原样迁移

**迁移原则：**
- ✅ 移动所有文件（ipynb, zip, pdf, md 等）
- ✅ 保持原始目录层级
- ✅ 保持原始文件名
- ❌ 不分析内容
- ❌ 不转换格式

**输出：**
```
raw-material/
├── Part 1. 大模型RAG入门基础架构与实战/
│   ├── 大模型RAG入门基础架构与实战.ipynb
│   └── 其他资料.zip
├── Part 2. 大模型RAG进阶多格式文档解析实战/
│   └── ...
```

---

### 阶段 3: 知识框架设计

**执行者：** 子智能体 B（Framework Designer Agent）

**职责：**
1. 读取 `raw-material/` 中的原始资料，提炼核心知识点
2. 设计企业级知识框架
3. 框架要分层次（基础 → 进阶 → 高级）
4. 结合联网搜索补充最新知识点

**输出：**
```json
{
  "framework_name": "RAG实战课程知识框架",
  "levels": [
    {
      "level_name": "基础",
      "modules": [
        {
          "module_name": "模块 1.1: RAG基础认知",
          "learning_objectives": ["理解RAG核心思想", "掌握三步流程"],
          "estimated_duration": "2-3天"
        }
      ]
    }
  ],
  "total_modules": 8,
  "total_duration": "约2-3周"
}
```

**持久化：**
1. `KNOWLEDGE_FRAMEWORK.json`
2. `README.md` 的 `## 知识框架` 章节

---

### 阶段 4: 内容结构规划

**执行者：** 子智能体 C（Content Planner Agent）

**职责：**
1. 基于知识框架划分课程结构
2. 设计每节课的标题、核心知识点、教学目标
3. 规划配套代码案例

**输出：**
```json
{
  "course_name": "RAG实战课程",
  "total_lessons": 9,
  "lessons": [
    {
      "lesson_id": "01",
      "title": "RAG基础：为什么需要检索增强",
      "slug": "rag-basics-why-retrieval-augmentation",
      "core_knowledge_points": ["大模型四大局限", "三种知识注入方案"],
      "teaching_objectives": ["理解幻觉问题", "掌握RAG核心思想"],
      "content_file": "lessons/01-rag-basics-why-retrieval-augmentation/content.md",
      "code_examples": []
    }
  ]
}
```

**持久化：**
1. `CONTENT_STRUCTURE.json`
2. `README.md` 的 `## 内容结构设计` 章节

---

### 阶段 5: 框架与结构审核

**执行者：** 子智能体 D（Reviewer Agent）

**职责：**
1. 审核知识框架覆盖度
2. 审核课程结构合理性
3. 提出修改建议

---

### 阶段 6: 任务拆分与规划

**执行者：** 子智能体 E（Planner Agent）

**职责：**
1. 将课程拆分为独立任务（每节课一个任务）
2. 分组可并行执行的任务

---

### 阶段 7: 并行内容构建

**执行方式：** 滚动窗口式并行，窗口大小=2

**每组 3 个子智能体：**

| 智能体 | 职责 |
|--------|------|
| R (Reader) | 读取原始资料中相关内容 |
| W (Writer) | 编写 content.md + 代码案例 |
| C (Checker) | 审核内容，最多 3 次修复 |

---

### 阶段 8: 最终审核

**执行者：** 子智能体 F + G（交叉审核）

**职责：**
1. 全面审核所有内容
2. 检查内容正确性、完整性
3. 检查代码可运行性

---

### 阶段 9: 生成产物

**执行者：** 主智能体

**职责：**
1. 生成项目根目录的 `.gitignore`
2. 更新 `README.md` 的项目结构章节
3. 整理最终目录结构

## 关键约束

1. **目录扁平化**：学习内容直接在项目根目录，不嵌套 `output/` 目录
2. **资料原样迁移**：raw-material/ 中的资料保持原始结构和文件名
3. **全自动执行**：所有阶段全自动执行，无需用户确认
4. **代码与文档并重**：每节课既有 content.md 理论文档，也有可运行的代码案例

## 注意事项

1. **执行模式**：此 Skill 需要多智能体环境支持
2. **进度追踪**：每个阶段完成后输出状态报告
3. **错误处理**：某节课构建失败不影响其他课程继续执行
